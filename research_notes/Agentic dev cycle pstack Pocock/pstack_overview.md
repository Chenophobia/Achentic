## 1. What is pstack? (canonical URL, structure, install, harnesses)

### Takeaway
pstack exists and is real: it is an MIT-licensed agent-skills plugin authored by Lauren Tan ("poteto"), living not in her own GitHub account but as the `pstack/` directory of Cursor's official `cursor/plugins` repo. It is Cursor-first, with an officially generated Claude Code build in the same repo; every other harness (Codex, Pi, OpenCode, Hermes, T3 Code, etc.) is served by community ports. It is not related to Garry Tan's gstack (and not the Unix `pstack` stack-trace tool).

## 2. Full inventory (skills, playbooks, subagents, principles, automations, scripts)

### Takeaway
Current upstream (v0.15.46) ships 34 workflow skills + 24 one-principle skills (58 skill folders), 22 playbooks inside `poteto-mode`, 2 subagents, 1 worker contract file, 1 dormant Slack automation pack ("benny") with 3 unregistered skills, and bundled helper scripts. No hooks, no shipped rules.

### Cited Findings

**Entry point and router**
- `/poteto-mode` — "default entry point for any non-trivial task"; matches the task to a playbook, copies its steps verbatim into a todo list, routes to other skills as steps fire, and writes "unslopped replies". Frontmatter has `disable-model-invocation: true` (only runs when the user types it) — [README](https://github.com/cursor/plugins/blob/main/pstack/README.md); [MODE](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md)
- `poteto-mode/worker.md` — contract every spawned agent must read first ("Read <path>/worker.md before anything else."): the kickoff's bar is the whole bar; never show a person a question; decide reversible calls; stop only for deploy, deleted data, force-push to a shared branch, or an outside message; open PRs ready (never draft); PR title `type(scope): subject`; PR body ≤40 lines with headings `Why`, `What changed`, `Scope`, `Tradeoffs`, `Blast Radius`, `Verification` — [worker.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/worker.md)
- Bundled scripts under `poteto-mode/scripts/`: `watch-pr/` (TypeScript GitHub PR watcher with tests, used by Babysit/Shipping, supports `--status-only` and `--queued-stack`), `worktree-audit.sh`, `bootstrap.ts`; plus `references/bugbot-triage.md` — [poteto-mode folder](https://github.com/cursor/plugins/tree/main/pstack/skills/poteto-mode)

**The 34 workflow skills** (descriptions from the README "all skills" table) — [README](https://github.com/cursor/plugins/blob/main/pstack/README.md)
- Orientation/prompting: `/poteto-help` (which skill fits; answers and hands back a prompt, doesn't start work), `/in-your-own-words` (agent plays back your goal and problem before starting), `/sharpen` (rewrites a prompt "deeper, not bigger": what a top professional would do, raw material, methods, outside check; doesn't do the task).
- Understanding: `/how` (walkthrough of a subsystem), `/why` (why it was built this way, answered "from the record, not the code": commits and PR discussions, marks inferences), `/teach` (runs how + why into one explanation built diagram by diagram), `/recall` (rebuild recent context on a topic from your own chat history), `/ketchup` (what changed in this chat since your last message + each decision waiting on you), `/ketchup-video` (same as a subtitled slide video), `/bro` (restate last message in plain human language).
- Design: `/architect` (settle caller usage, types, module shape before code that crosses a function boundary), `/arena` (N parallel attempts at the same brief, then graft the best parts), `/swarm` (N parallel workers across slices or races, one aggregated report), `/interrogate` (different models try to break a diff; keeps only findings a run proves), `/blast-radius` (what else a small change could break; the one safety fact is proven by running code), `/figure-it-out` (designs an auditable playbook when none fits).
- Build/clean: `/tdd` (failing test first when there is a cheap local test path), `/typescript-best-practices`, `/no-comments` (strip comments before review; spawns Comment Sicko), `/unslop` (remove AI tells from prose), `/technical-writing` (layered doc standard: Diátaxis + Google developer style + STE + Global English).
- Verification: `/benchmark-checklist` (vet a measured number), `/create-verification-skill` / `/maintain-verification-skill` (generate/maintain a project-local `verify-<app>` skill with a feature map), `/create-formal-verification-skill` / `/maintain-formal-verification-skill` (verify one property with a model checker/verifier and generate a project-local recheck skill), `/statechart` (TLA+ model → Mermaid statechart of what the user sees, with rule-breaking states marked).
- Audit/learning loop: `/show-me-your-work` (decision trail logged to a TSV), `/reflect` (capture a session's lessons as a skill edit), `/correct` (mine history for repeated mistake classes and fix each at the highest structural level), `/automate-me` (draft your own `<name>-mode` skill from your transcripts).
- Config/misc: `/setup-pstack` (per-role model + reasoning budget; writes the model rule), `/make-bot-ui` (page whose buttons wake a "Grok Bot" via webhook; Tailscale).

**The 22 playbooks** (in `poteto-mode/playbooks/`) — [README](https://github.com/cursor/plugins/blob/main/pstack/README.md); [PLAYBOOKS](https://github.com/cursor/plugins/tree/main/pstack/skills/poteto-mode/playbooks)

## 3. End-to-end workflow, named phases and artifacts

### Takeaway
pstack deliberately has no spec→plan pipeline. The flow is: state a goal plus a checkable "done" → `/poteto-mode` routes to a playbook → understand (trace/how/why) → design through code (`/architect`, prototypes, `/arena`) → delegate implementation to subagents while the main chat stays "in the lead" → verify on the real artifact → clean (deslop/unslop/no-comments) → small ordered commits and a briefing-style PR → Babysit to merge-ready → Shipping lands only independently verified PRs. Plans are optional, written only after design settles.

### Cited Findings
- No planning skill, by design: "cursor already has a great plan mode which works great with pstack. but personally, i don't believe in planning. the best spec is code. if you do want to make a plan, `/poteto-mode` covers it, but it's not a default." — [README](https://github.com/cursor/plugins/blob/main/pstack/README.md)
- "You plan through code. Prototypes answer the open questions, a README or tutorial sets the target, and the written plan comes last." — [GUIDE/04-design.md](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/04-design.md)
- Guide chapter order = the prescribed lifecycle: 1 Set up; 2 Route work through `/poteto-mode`; 3 Understand the code (`/how`, `/why`, `/teach`, `/recall`); 4 Design the change (`/architect`, `/arena`, `/swarm`, `/interrogate`, prototypes, plans); 5 Build and clean (`/tdd`, `/unslop`, `/no-comments`); 6 Verify and ship; 7 Run work while you sleep; 8 Steer with principle names; 9 Make it yours; 10 Recipes and pitfalls — [docs/guide/README.md](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/README.md)
- Prompt contract (in place of a spec): a prompt carries up to five things — the goal, the done check ("It must be able to pass or fail"), the proof you want to see, what you already know, and the real constraints. Leave out "the how" and, at first, your theory of the cause — [GUIDE/02-poteto-mode.md](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/02-poteto-mode.md)
- Router behavior: read the Principles section → match the task → playbook steps copied into the todo list; large, cross-cutting, or unattended work, or no match, routes to `figure-it-out` — [MODE](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md)
- Feature playbook steps: (1) trace the affected subsystem; (2) `architect` for the shape; (3) write a four-item "throughput checkpoint" (blocking first steps, independent workstreams, shared mutable state, smallest safe decomposition); (4) delegate code-writing to a subagent with a specific scope (mandatory; use `arena` when multiple valid shapes exist); (5) verify on the matching surface — "'Inconclusive' or wrong-surface is not a pass"; (6) rebase into small ordered commits, stack follow-ups; (7) `interrogate` if the design is contested; (8) Opening a PR — [playbooks/feature.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/feature.md)
- Bug fix playbook: reproduce yourself on the matching surface; binary-search the cause with runtime evidence; plan the fix (`architect` if it crosses a function boundary) and delegate; verify the original repro now passes; stage commits so the failing repro lands before the fix; Opening a PR. "Every shipped line traces to runtime evidence." — [playbooks/bug-fix.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/bug-fix.md)
- Multi-phase plan playbook (the only "plan" artifact): skip the plan for one- or two-file obvious changes; settle open questions by prototype first; plan file opens with what changes, PR ids in landing order, and a dependency graph; one section per PR with checkboxes (dependencies, files, the one change, the visible result, verification); "Tests alone are not sufficient verification" — each PR needs unit, live, and perf boxes; hand back the plan path and stop until the operator says go — [playbooks/multi-phase-plan.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/multi-phase-plan.md)
- `figure-it-out` phases for large/unattended work: A Frame (falsifiable definition of done, quantified scope, rigor level), B Design the workflow (atomic landable units, riskiest-unknown-first, build the verification harness before the work), C Run the loop (each unit an experiment; verdicts VERIFIED / NOT VERIFIED / INCONCLUSIVE), D Keep the audit trail, E Verify and hand back — [skills/figure-it-out/SKILL.md](https://github.com/cursor/plugins/blob/main/pstack/skills/figure-it-out/SKILL.md)
- Opening a PR: work from a git worktree off trunk; rebase into small landable commits; run `/deslop` before commit; title `type(scope): subject`; body "a one-minute briefing under 40 lines" with `## Why`, `## What changed`, `## Scope`, `## Tradeoffs`, `## Blast Radius`, `## Verification`; open ready, not draft — [playbooks/opening-a-pr.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/opening-a-pr.md)
- Babysit: modes `drive` / `threads-only` / `check`; blocker order conflicts → review threads → CI; never rebases, retargets, or force-pushes; "stops at merge-ready. It never merges" — [playbooks/babysit.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/babysit.md); [GUIDE/06-verify-and-ship.md](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/06-verify-and-ship.md)
- Shipping: one independent verifier per PR posts `PASS`, `PASS+NOTES`, or `FAIL`; "Only a verdict from an agent that did not write the code counts"; "Green CI and an approving bot review are not verdicts"; land only the contiguous verified run from the bottom, one PR at a time (`gh pr merge --squash` or Origin CLI; "Never require Graphite"); re-check verdicts with `git patch-id` after rebases — [playbooks/shipping.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/shipping.md)
- Autonomous/overnight: exit condition stated as a checkable predicate; wake via Cursor's `/loop`; each iteration = smallest justified change → verify → commit or discard → one decision-log row; "never relax the predicate to declare victory" — [playbooks/autonomous-run.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/autonomous-run.md)
- Named artifacts: todo list seeded from playbook steps; throughput checkpoint; prototype scratch dir with a variant switcher; optional plan file; `decisions.tsv` (or `.audit/<task-slug>.tsv`) with time, phase, decision, reason, evidence pointer, result; project-local `.cursor/skills/verify-<app>/` skill with Launch/Doctor/Drive/Evidence/Cleanup sections and a `features/` feature map; formal-verification skill; resume note from Pause safely (e.g. `/tmp/<slug>-resume.md`); `wip:` checkpoint commit; PR verdict comments; `~/.cursor/rules/pstack-models.mdc` — [GUIDE/06](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/06-verify-and-ship.md); [GUIDE/07](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/07-overnight.md); [playbooks/pause-safely.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/pause-safely.md)
- Design-effort ladder: small finished change you doubt → `/interrogate` alone; crosses function boundaries → `/architect`; standalone decision → `/arena`; coverage matrix → `/swarm`; question answerable by running something → prototype; contested expensive-to-reverse design → `/architect` then `/interrogate`; multi-PR work → a plan after design settles — [GUIDE/04-design.md](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/04-design.md)
- Learning loop after shipping: `/reflect` (session lessons → skill edit, needs approval), `/correct` (repo-level fixes ranked: architecture → types/lint/CI → tests → docs last), `/automate-me` (personal mode), Eval playbook (blinded A/B of skill changes) — [GUIDE/09-make-it-yours.md](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/09-make-it-yours.md)

### Inferences
- Mapping to a conventional idea→spec→plan→implement→review→ship pipeline: idea = goal + done-check prompt (optionally `/sharpen`, `/in-your-own-words`); spec = replaced by prototypes, `/architect` output (types/signatures/module boundaries), or a README/tutorial written first; plan = optional Multi-phase plan file; implement = delegated `poteto-agent` subagents; review = `/interrogate` (multi-model, evidence-only findings), `/no-comments`, independent verifier agents; ship = Opening a PR → Babysit → Shipping (or Autopilot-full/stack for queues).
- The main chat acts as lead/orchestrator ("You own the design. Plan, review, verify. Delegate implementation."), so the methodology is structurally multi-agent even for a single feature.
- Separation of author and judge is a recurring structural rule (cross-vendor arena judge, non-author verifier in Shipping, Comment Sicko as non-author reviewer, different-model-family reviewer in `/show-me-your-work`).

### Gaps
- The exact step lists of the Refactoring, Prototype, Perf, Hillclimb, Eval, Autopilot-full, Session pickup, Visual parity, forensics, and Worktree cleanup playbooks were only partially read (headers and first steps).

## 4. Principles Lauren states about agentic development (short quotes with URLs)

## 5. Recommended models, tools, harness settings, cost notes

### Takeaway
pstack is explicitly multi-model and role-based: Opus 5.5 at xhigh reasoning does code, prose, and judgment; review/design panels mix three seats (Fable 5.2, Opus 5.5, Gemini 4 Neon) for vendor diversity; nothing runs above xhigh; and a three-level budget (`large`/`medium`/`small`) scales reasoning effort. She states plainly that the rigor costs tokens.

### Cited Findings
- Out-of-the-box defaults: "code delegates (feature, refactoring, bug fix, perf, hillclimb), prose, and judgment go to opus 5.5 at xhigh, and no role runs above xhigh. outside a review panel, fable 5.2 runs only when you name it or after two opus 5.5 runs of the same brief fail. the default panel is fable 5.2 / opus 5.5 / gemini 4 neon." — [README](https://github.com/cursor/plugins/blob/main/pstack/README.md)
- Exact default slugs (Cursor): code/prose/judgment `claude-opus-5-5-xhigh-fast`; trivial mechanical edits and swarm workers `claude-opus-5-5-high-fast`; panels one runner each on `claude-fable-5-2-high`, `claude-opus-5-5-high-fast`, `gemini-4-neon-xhigh`; arena cross-judge pool `claude-opus-5-5-high-fast, gemini-4-neon-xhigh`; "Opus 5.5 always runs its `-fast` slug"; verification always runs on the `swarm workers` model — [MODE](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md); [setup-pstack SKILL.md](https://github.com/cursor/plugins/blob/main/pstack/skills/setup-pstack/SKILL.md)
- Roles configurable in the rule file: `feature, refactoring`, `bug-fix`, `perf-issue`, `hillclimb`, `judgment and prose`, `arena runners`, `arena cross-judge pool`, `swarm workers`, `interrogate reviewers`. Rule file: `~/.cursor/rules/pstack-models.mdc` (`alwaysApply: true`, marker `# defaults: 3`) — [setup-pstack SKILL.md](https://github.com/cursor/plugins/blob/main/pstack/skills/setup-pstack/SKILL.md)
- Budgets: `large — xhigh reasoning` (= defaults), `medium — high reasoning` (each role one step lower), `small — medium reasoning` (two steps lower) — [setup-pstack SKILL.md](https://github.com/cursor/plugins/blob/main/pstack/skills/setup-pstack/SKILL.md); [GUIDE/01-setup.md](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/01-setup.md)
